# CPU 历史 KV 的 INT4 正式验收条件

冻结于 2026-11-23，正式性能和质量输入均在冻结后运行。这些阈值用于本机的启用判断。模型为 Qwen3-4B，权重和活跃 GPU 页为 BF16，卡为单张 RTX 3090。软件开关为 `cpu_prefix_cache_format="int4"`。参考实现与本机结果分开核算。

## 配置与输入

- 性能探索种子 3400，正式种子 3501–3506。三臂分别为 BF16 64 slots、INT4 64 slots、BF16 18 slots。前两臂的实际保存与恢复块数必须一致。后两臂的可分页 CPU 页池均为 648 MiB。单列锁页缓冲、分配器、索引、总 RSS 和 GPU 池。
- 三臂都用 36 个 GPU 块、256 tokens/块、每步 2048 tokens、并发 4、CUDA Graph、冷合批、overlap、reuse 准入与首次额度 32。小缓存的首次额度自然受 18 slots 上限约束。每波固定输出 16 个 greedy tokens。单独的进程加载每臂与种子，触碰全部 CPU 页，另用种子 3499 预热，然后清空缓存索引。六个种子覆盖三臂的全部六种顺序。
- 混合工作集每波四条，历史前缀 1024/2048 tokens，加 128 个新输入。计入冷填充、GPU 热重放、两波无复用和淘汰重放。容量工作集用四组前缀，每组 4 × 1024 tokens，合计 64 个历史块。逐组填充并立即触碰一次，最后轮流重访。性能测量保留正常 GPU 淘汰。记录每条请求从入队到首个真实 token 的 TTFT，逐波结束前收齐后台写入。
- 质量探索种子 3100。正式种子 3201、3202，每种子测 2048、8192、12288-token 前缀，各在 10%、50%、90% 深度放置随机验证码。每组有单跳和两跳各一题，两跳的票据指针与验证码分开放置，共 36 题。在相同批形状下用未压缩 GPU 页作配对参照。清空空闲 GPU 查找索引、保留 CPU 页，强制每条质量样本真实恢复整个前缀。质量诊断的时延排除在性能数据外。
- 任务分数按 EOS 前文本提取，移除所查询或中转的带前缀 ID，要求仅有一个不同的六位数且等于独立生成的答案。另报严格只输出数字的条数、原文相同条数、真正答错的样本。另用相同引导语逐位置强制六个金标准数字，并沿 BF16 的自然 greedy 回答逐位置回放至 EOS，最多 32 个位置，两者均比较完整词表 logits。

## 判据

| 项目 | 达标线 |
| --- | --- |
| 容量、传输与安全性 | 同块数的实际 slot 和单向 DMA 字节均不超过 BF16 的 1/3。相同页池字节至少容纳 3 倍完整有效块，容量轨迹确实填满两档。已知索引精确，恢复覆盖预期连续前缀，正式记录无传输失败或抢占。 |
| 同 slot 的恢复收益 | 混合淘汰重放的 INT4 p95 TTFT 较 BF16 64 slots 下降至少 15%，配对种子 95% 区间上界小于零。 |
| 同页池字节的容量收益 | 容量轨迹的延迟重访段，INT4 相对 BF16 18 slots 的 p95 至少下降 30%，区间上界小于零，完整恢复条数增加。 |
| 延迟副作用 | 同 slot 的混合整段、混合无复用段及容量整段 p95 点估计各至多上升 5%。各段都报告原数与配对区间。按完整种子重采样 4000 次，每次重算 pooled p95。 |
| 检索任务质量 | 每类 18 题的 BF16 至少答对 9 题才判该类。INT4 每类至多丢失 1 条 BF16 答对的题，12288 档两类合计至多丢失 1 条。原参照和重建 K/V、logits 应为有限值。 |
| 数值质量 | 各类金标准数字的逐位置 top-1 一致率至少 95%，平均目标负对数概率增量至多 0.15 nat/token。沿 BF16 自然回答的平均 KL 至多 0.20 nat/token，平均目标负对数概率增量至多 0.25 nat/token。单列 K/V 重建误差、自由生成文本变化和最大误差。 |

达到某项性能门槛只支持对应工作集。质量判据约束启用结论，格式或精确复现需求另看原文差异。默认仍用模型原生格式。单种子探索、质量钩子和单块 memcpy profiler 均单独归档。

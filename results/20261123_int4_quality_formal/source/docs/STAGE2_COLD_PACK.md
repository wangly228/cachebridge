# 基于前缀回放的冷请求合批实验

**保留可选的冷请求合批。** 六个新种子下，含冷填充的混合整段 p95 从 927.27 ms 降至 880.04 ms，相对当前版变化 -5.09%（-7.57% 至 -3.20%）。同轮原生 A 为 917.96 ms，候选相对 A 变化 -4.13%（-5.96% 至 -2.86%）。六项预设判据均通过。全长淘汰重放 p95 比 overlap 32 高 3.57%（配对 95% 区间 +0.05% 至 +4.11%），低于 5% 分段上限。各组使用相同 FIFO 到达顺序和每步 token 上限。合批让队尾少等若干轮前向，也会让较早完成的请求等同批后续请求的前向结束。[三臂逐请求结果](../results/20261123_cold_pack_formal/requests.jsonl) · [正式汇总](../results/20261123_cold_pack_formal/summary.json)

## 改动依据

沿用 PrefixSim 提交 `160d5f81724dd9ec28b10d6abb64615e6adbb332` 按重算成本比较前缀策略的思路，回放时使用 cachebridge 的 GPU/CPU 两层块状态、256-token 块、连续前缀及尾查询约束。上轮 66⅔% 档中，96 条重访有 33 条未完整恢复。按第一个缺块归因，27 条在准入时未写入，另 6 条被 LRU 淘汰。离线把首次写入限额放宽到所有空 slot，使该档完整恢复从 63 增至 84 条，但无复用档会多写 128 块。旧六种子主负载的淘汰重放已经全部完整恢复。[逐块归因和新轨迹复跑](STAGE2_PREFIX_REPLAY.md) · [成本、排队与 p95 排名敏感性](../results/20261123_prefix_replay_cost/analysis.md)

主负载混合冷填充的 12 波总计 79,872 个 query tokens。旧策略执行 60 个 prefill 步，有 43,008 个未使用的预算位置。两条支撑整段 p95 的请求均在第 5 步取得首 token。候选保留原有 overlap 32 缓存，只让队首下一条全冷的新请求使用当前步的剩余预算。至少剩一个块的预算才允许分块接纳。同批若有请求即将发布相同根块，则等待它发布，以保留共享机会。已经命中前缀、抢占后重入和触发恢复选路的请求保留原有处理。开关可在常规 `LLM(..., cpu_prefix_pack_cold=True)` 启用，默认关闭。在已配置的 overlap 32 实例上添加这一参数即可复现候选。该配置同时启用按复用准入、32 块首次写入额度和后台批量搬运。正式实验记录各臂实际开关，重访比例实验另外从该候选配置直接构造 LLM。[调度器](../nanovllm/engine/scheduler.py) · [配置](../nanovllm/config.py) · [针对性测试](../tests/test_phase1.py)

独立输入测试从 20 个冻结请求只取输入与输出 token IDs，重新生成回放，逐项对齐 300 个计数。延迟模拟搬运期间，649 个调度步逐块核对了活跃引用，7 批后台写入覆盖 30 块，24 次恢复均获得独占 GPU 目标。本轮候选正式轨迹的 432 条请求、108 波、14,028 个调度步也均通过事后回放校准。另一个共享前缀样本有 7 步两个活跃请求持有同页，后到请求复用了 1,024 个 tokens。真实 CUDA 上的 KV 往返逐位检查包含在本轮 51 项测试中。[保护条件审计与重跑](../results/20261123_prefix_replay/protection/audit.json) · [正式候选校准](../results/20261123_prefix_replay/cold_pack_formal/summary.json) · [测试日志](../results/20261123_cold_pack_tests.txt)

## 实机测量

## 重访比例边界

独立种子 2201–2204，每个周期从空索引开始，连续执行 9 波。每档、每臂 144 条，合计 1,296 条正式请求。初始 GPU 前缀命中均为零。取完整序列 p95（ms），包括前三波首次填充和随后的所有请求。区间按种子配对重采样。完整恢复数以实际 CPU 恢复的 tokens 与目标前缀长度相等计。[边界设计](../results/20261123_cold_pack_boundary/design.json) · [逐档汇总](../results/20261123_cold_pack_boundary/summary.json)

三个实测档位中，候选相对 overlap 32 和原生 A 的整段 p95 均下降，六个配对区间全部低于零。各档独立包含首次填充。两条 CPU 路径在三档写入分别为 128、240、292 块，恢复分别为 0、128、380 块，实际计算分别为 239,616、206,848、142,336 个 prompt tokens。最高重访档的完整恢复仍为 63/96。零恢复的 0% 档也观察到整段改善，说明合批本身即可改变尾延迟。边界实验校准了每个实际调度步、恢复计数和计算量。同形状的完全冷计算做逐 token 校验，A 与候选跨执行形状的完整 greedy 序列相同 259/432 条。两个 CPU 臂有 72 条请求的本次执行形状相同、缓存 KV 的生成批次形状不同，完整输出相同 60 条。更密的比例、连续在线到达、其他设备和模型均未测。[边界逐请求样本](../results/20261123_cold_pack_boundary/requests.jsonl)

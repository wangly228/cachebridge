# 阶段 2 首次写入额度对照

**32 块是本轮三档中，能在两种负载同时达标并保住全部首次重放命中的最小额度。** 每种负载各 8 个周期，32 相对 36 块都少写 32 个 KV 块（1.125 GiB），两种负载各 16 条先淘汰再首次重放的请求都完整恢复。整段 p95 相对 36 块在混合负载高 0.32%，在全长负载低 0.73%，两个 95% 配对种子区间均跨过零。[预设筛选条件](../results/20261119_first_use_budget36/design.json) · [完整结果与区间](../results/20261119_first_use_budget36/summary.json)

## 额度如何起作用

按复用写入策略在 CPU 索引较空时保存第一次出现的完整 prompt 块。达到首次写入额度后，新块需要在有界历史中被两个不同请求观察到，才能写入。已识别的复用仍可占用剩余 CPU slot。实验入口在每次冷启动后、首条请求入队前设置现有块管理器的 `first_use_limit`。A 使用原生 GPU 缓存，三个 CPU 组都使用按复用写入、双缓冲和命中即恢复，只有首次写入额度取值不同。引擎原有计算方式是 `min(GPU 块数, CPU slot 数)`，本机对照值为 36。[块管理器](../nanovllm/engine/cpu_prefix_cache.py) · [实验入口](../benchmarks/first_use_budget.py)

## 负载与对照

## 通过常规引擎设置额度

2026-11-20 起，调用方可以在构造 `LLM` 时设置首次写入额度。以下示例使用本轮的缓存容量和写入策略。

```python
import os

from nanovllm import LLM

llm = LLM(
    os.environ["MODEL_DIR"],
    max_kvcache_blocks=36,
    cpu_prefix_cache_blocks=64,
    cpu_prefix_admission="reuse",
    cpu_prefix_batch_writes=True,
    cpu_prefix_first_use_blocks=32,
)
```

`cpu_prefix_first_use_blocks` 接受 `None` 或非负整数，单位是完整 KV 块。省略或传 `None` 时取实际 GPU 块数与 CPU slot 数的较小值。显式传入 n 时，有效额度为 `min(n, 实际 GPU 块数, CPU slot 数)`。达到额度后，同一前缀由另一个请求再次使用仍可写入其余 CPU slot。设为 0 时从第一次访问就开始记录复用，第二个请求可触发写入。额度只对 `reuse` 生效，`always` 仍保存符合条件的完整 prompt 块。策略 C 的成本表按实际生效的额度区分，等同于自动值的配置可使用原有同环境成本表。[配置字段](../nanovllm/config.py) · [调度器](../nanovllm/engine/scheduler.py) · [成本表环境](../nanovllm/engine/restore_policy.py)

**常规入口验收通过。** 两次从 `LLM(...)` 启动 Qwen3-4B BF16，实际 GPU / CPU 容量均为 36 / 64 块。省略参数的实例采用 36 块，16 条短请求写入 36 块、恢复 32 块，与历史自动额度等价组逐条相同。显式 32 块实例完成 20 条短检，再用历史 32 块组的 4 个种子、两种访问顺序回放 288 条正式输入。两种负载每条请求的写入、恢复、实际 prefill 计算量、调度步和 128-token greedy 输出均与归档一致，抢占、保存和恢复失败均为 0。[实际构造参数](../results/20261120_first_use_config/engine.json) · [逐请求日志](../results/20261120_first_use_config/requests.jsonl) · [核验汇总](../results/20261120_first_use_config/summary.json)

**按冻结环境重测 GPU。** 历史脚本会核对 Git 基点和引擎源码的 SHA256。公开版有独立的 Git 历史，需要在临时目录检出原上游提交，再叠加该次测量的源码快照。以下命令从公开仓库根目录执行。当前工作目录提供 `results/` 下的基线输入和上一轮环境记录，`PYTHONPATH` 指向临时目录以加载冻结引擎。每次运行都创建新的输出目录。

```bash
(
  set -eu
  frozen_checkout=$(mktemp -d)
  upstream_commit=bb823b3e06983d71485a8e1f23715ebd87d98ef8
  git -C "$frozen_checkout" init -q
  git -C "$frozen_checkout" fetch -q --depth=1 https://github.com/GeeeekExplorer/nano-vllm.git "$upstream_commit"
  git -C "$frozen_checkout" checkout -q --detach "$upstream_commit"
  cp -a results/20261119_first_use_budget36/source/. "$frozen_checkout/"
  echo "本轮 GPU 测量输出目录为 $frozen_checkout/run"
  PYTHONPATH="$frozen_checkout" .venv/bin/python -P -m benchmarks.first_use_budget \
    --model "${MODEL_DIR:-$HOME/models/huggingface/Qwen3-4B}" --output "$frozen_checkout/run"
)
```

两处 GPU 回放命令都检查 GPU 型号、计算能力、CUDA runtime、依赖版本和模型文件清单。冻结清单含权重 SHA256，也含 Hugging Face 下载元数据中的时间戳；重新下载相同 revision 可能触发 `model_files` 校验失败。其他环境可使用上面的离线复核命令，或运行 [README 的三请求恢复示例](../README.md#在本机观察一次-cpu-恢复) 检查本机行为。

# 阶段 2 首次写入额度对照

**32 块是本轮三档中，能在两种负载同时达标并保住全部首次重放命中的最小额度。** 每种负载各 8 个周期，32 相对 36 块都少写 32 个 KV 块（1.125 GiB），两种负载各 16 条先淘汰再首次重放的请求都完整恢复。整段 p95 相对 36 块在混合负载高 0.32%，在全长负载低 0.73%，两个 95% 配对种子区间均跨过零。[预设筛选条件](../results/20261119_first_use_budget36/design.json) · [完整结果与区间](../results/20261119_first_use_budget36/summary.json)

## 额度如何起作用

按复用写入策略在 CPU 索引较空时保存第一次出现的完整 prompt 块。达到首次写入额度后，新块需要在有界历史中被两个不同请求观察到，才能写入。已识别的复用仍可占用剩余 CPU slot。实验入口在每次冷启动后、首条请求入队前设置现有块管理器的 `first_use_limit`。A 使用原生 GPU 缓存，三个 CPU 组都使用按复用写入、双缓冲和命中即恢复，只有首次写入额度取值不同。引擎原有计算方式是 `min(GPU 块数, CPU slot 数)`，本机对照值为 36。[块管理器](../nanovllm/engine/cpu_prefix_cache.py) · [实验入口](../benchmarks/first_use_budget.py)

## 负载与对照

RTX 3090 24 GB，Qwen3-4B revision `1cfa9a7208912126459214e8b04321603b3df60c`，权重和 KV 均为 BF16。GPU 36 块、CPU 64 块，每块 256 tokens、36 MiB。每波并发 4，每条前缀后追加 128 个输入 tokens，用 greedy 生成 128 个 tokens，每步 prefill 预算为 2048 tokens。启用 CUDA Graph，关闭 profiler。三个 CPU 组各有相同的 2.25 GiB 主存容量和 72 MiB 锁页暂存，设备端暂存 36 MiB。三组与 A 在同一进程中共用已分配的张量，A 的 CPU 索引和传输关闭。环境、模型文件和引擎源码摘要与上轮混合实验核对。[引擎配置及额度](../results/20261119_first_use_budget36/engine.json) · [软硬件与源码](../results/20261119_first_use_budget36/environment.json)

4 个新种子 1801–1804，每种负载、每种额度各跑 8 个冷启动周期。每个种子既跑“填充 → 热重放 → 干扰 → 淘汰重放”，也跑“填充 → 干扰 → 淘汰重放 → 热重放”。同一周期四个对照的输入 IDs 和到达顺序相同，开局 GPU 和 CPU 缓存索引都为空。按负载和访问顺序分别轮换四个策略，每个策略在四个测量位置各出现一次。[固定输入](../results/20261119_first_use_budget36/trace.json) · [预设条件和轮换顺序](../results/20261119_first_use_budget36/design.json)

| 每种策略的采样范围 | 混合 1024 / 2048 | 全 2048 |
| --- | ---: | ---: |
| 每波 4 条的前缀分布 | 各 2 条 | 4 条相同长度 |
| 每周期独立干扰波数 | 2 | 1 |
| 含填充的整段请求数 | 160 | 128 |
| 冷填充 / 热重放 / 淘汰重放请求数 | 每段 32 | 每段 32 |
| 无复用请求数 | 64 | 32 |
| 淘汰重放中，先淘汰再首次复用的子组 | 16 | 16 |

混合波峰值占 28 个 GPU 块，使用两波全新前缀制造淘汰。全长波占满 36 块，一波干扰即可。淘汰重放是否实际 GPU 零命中，按原始请求逐条检查。填充和重放使用相同前缀、不同输入尾部，热重放和淘汰重放使用相同的完整输入。[逐请求记录](../results/20261119_first_use_budget36/requests.jsonl) · [逐波占用](../results/20261119_first_use_budget36/waves.jsonl)

以入队到首个真实输出 token 的时间计算 p95，整段计入冷填充、写入、恢复和等待。每个周期计时结束后写盘。种子 1800 的预热请求在原始日志中标为 `warmup=true`，额外的原生数值对照保存在 `reference/`。正式统计排除这两部分。对普通完整恢复，用原生 GPU 热命中作同形状参照。对全长 24 块先淘汰的路径，原生 GPU 先真实填充三个目标前缀和一个无关前缀，再依次处理原始重放和热重放。核对每步 prefill/decode 类型、计算量、入批位置和完整 greedy 输出。[额外原生对照](../results/20261119_first_use_budget36/reference/requests.jsonl) · [调度记录](../results/20261119_first_use_budget36/steps.jsonl)

无复用 p95 相对同轮 A 上升不超过 5%，淘汰重放 p95 相对 A 至少下降 20%。在两种负载都达标、并保留所有“先淘汰再首次复用”恢复的额度中，取本轮测过的最小值。整段 p95 同时与 A 和 36 块比较。配对 95% bootstrap 区间按种子整组重采样 4000 次，每次保留两个周期和波内相关请求。[统计与核对入口](../benchmarks/first_use_budget_report.py)
